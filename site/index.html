How it works

Four steps, one of which leaves the machine

Most "AI for your data" tools ship your data to a model and hope you don't read the privacy policy. POND inverts it: the model gets a schema and a sentence, and the answer is computed on your laptop.

01 · LOCAL

Import

Point pond import at a zip, folder, or file. It auto-detects the source and normalizes everything into curated tables.

02 · LOCAL

Store

One DuckDB file at ~/.pond/pond.duckdb. A sha256 ledger plus per-row dedupe keys make every re-import a no-op.

03 · THE ONE HOP

Translate

Your question and the schema DDL go to Claude. It returns SQL. That is the entire payload — run pond schema to read it verbatim.

04 · LOCAL

Execute

sqlglot validates the SQL — single statement, SELECT only, no file access — then DuckDB runs it locally and Rich prints the table.

The privacy contract is inspectable, not aspirational. pond schema prints the exact bytes pond ask would send. If you set privacy.vocab_sharing: none, even category names stay home. Narrations, messages, search queries and video titles are never in the payload under any setting.

Features

Built for the awkward questions

The interesting questions about your own life are cross-source and full of gaps. POND is designed around exactly that.

Absence is data

"Weeks I skipped gym" means rows that don't exist. POND ships days and weeks calendar-spine views that manufacture those rows, so gap queries are a WHERE went_to_gym = FALSE instead of a headache.

Re-run anything, any time

A sha256 file ledger skips files you've already imported; a per-row dedupe key catches the overlap when two exports cover the same week. Imports are idempotent by construction, not by discipline.

The LLM is sandboxed

Generated SQL is parsed with sqlglot before it touches the database: exactly one statement, SELECT only, no DDL/DML/PRAGMA/ATTACH/COPY, and no read_csv-style functions that reach into the filesystem.

Banks, learned once

The first import of a new bank format asks four questions — which column is the date? the narration? one signed amount or separate debit/credit? — and saves the answers. Every import after that is silent.

An escape hatch that's honest

Some signals have no data trail. pond log gym writes one row and moves on — which is what makes "weeks I skipped gym" answerable before any Google Fit export exists.

SQL when you want it

pond sql runs raw queries with no LLM in the loop at all, and --format csv|json pipes straight into whatever you were going to do next anyway.

Data model

Eight curated tables and two views

Every timestamp is TIMESTAMPTZ in your local timezone. Every amount is signed, with negative meaning money out. Raw source rows are also staged into raw_* tables so nothing is lost in translation.

POND curated tables, their grain, and their most useful columns.
Table One row is Worth knowing
transactions one bank line amount (negative = spend), merchant, category
messages one WhatsApp message chat, sender, is_me, word_count
listens one Spotify play ms_played — filter >= 30000 for real listens
activities one workout or session activity_type, duration_min; also fed by pond log
daily_metrics one day of Google Fit steps, distance_m, calories
searches one Google search only genuine "Searched for …" entries
youtube_watches one video watch ads skipped; deleted videos keep a NULL channel
calendar_events one calendar entry recurring events stored as the master only
days / weeks a calendar spine (view) week_start, went_to_gym — this is how gaps get queried

Quickstart

Running in about four minutes

Python 3.11+ and uv. That's the whole prerequisite list.

  1. Install and initialise

    Creates ~/.pond with a config, starter category rules, and an empty database. 

    $ git clone https://github.com/charanreddy-27/pond
$ cd pond && uv sync
$ uv run pond init --name "YourWhatsAppName" --timezone "Asia/Kolkata"

  2. Feed it your exports

    Zip, folder, or single file — POND figures out the source. Every import reports rows inserted, duplicates skipped, and the new date range of each table it touched. 

    $ pond import my_spotify_data.zip
$ pond import takeout-20260101T000000Z.zip
$ pond import "WhatsApp Chat with Rahul.txt"
$ pond import stmt.csv --source bank --account hdfc_savings
$ pond status                 # what's in the pond

  3. Read the privacy payload first

    Before you send anything anywhere, look at exactly what would be sent. This is the step most tools don't let you take. 

    $ pond schema                 # the entire LLM payload, verbatim

  4. Ask

    pond ask needs an Anthropic key for the English-to-SQL hop. pond sql never does. 

    $ export ANTHROPIC_API_KEY=sk-ant-...
$ pond ask "top 5 artists by hours listened last month" --explain
$ pond sql "SELECT count(*) FROM listens"   # no LLM at all
