What I learned building this

Five lessons, plus one I didn't ask for

Not the tidy retrospective version. The parts that actually changed how I'd start the next one.

A privacy claim you can't print isn't a privacy claim

I started with "we only send the schema" in the README. That's a promise. So I built pond schema, which prints the exact payload pond ask would send — same function, same code path, no separate "documentation" version to drift out of sync. The moment the claim became a command, it became testable. It's the design decision I'm proudest of, and it took ten minutes.

LLM output is untrusted input. Treat it like a form field.

My first pass at SQL safety was a regex blocklist for DROP and DELETE. That is security theatre — it dies to a comment, a CTE, or a second statement after a semicolon. The real fix was parsing the SQL into an AST with sqlglot and walking every node: one statement, SELECT only, no filesystem-reaching functions. A prompt asking nicely is not a control.

Idempotency needs two layers, and I found that out the hard way

A sha256 file ledger stops you re-importing the same file. It does nothing when Spotify's "last year" export and the "lifetime" export both contain last March. Two different files, same plays, duplicate rows. The fix was a second layer — a deterministic per-row dedupe key — and the lesson was that "already imported?" and "already have this row?" are different questions.

Absence is the interesting half of the data

Nearly every question I actually wanted to ask was about a gap. Weeks I skipped the gym. Months I stopped texting someone. Gaps have no rows, and you can't GROUP BY nothing. So POND manufactures the rows — days and weeks calendar-spine views — and suddenly the LLM writes correct SQL for gap questions on the first try, because there's something to join against.

The human one: I kept automating a question I should have just asked

I burned an entire weekend on heuristics to auto-detect which column of a bank CSV is the date. Indian banks have opinions about this. Every fix broke a different bank. The version that shipped asks you four questions the first time it sees a new format, then saves the answers and never asks again. Fully automatic on every import but the first. I'd been optimising for a demo instead of for a user — and the user was me.

Bonus: it works, which is its own problem

The first genuinely useful answer POND gave me was a correlation between weeks I didn't train and weeks I ordered in. I did not need a p-value. I needed a different hobby. Building a tool that's honest with you is a slightly different experience from building one that's honest with a customer.
